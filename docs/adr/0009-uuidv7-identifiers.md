# 9. Generate UUIDv7 identifiers in the application

- **Status:** Accepted
- **Date:** 2026-07-28
- **Implemented in:** phase 2
- **Related:** ADR-0001, ADR-0008

## Context

Runs, steps, calls, facts and sources all need identifiers. Two requirements shape the
choice. Correlated logging must work **before** a row is written, because a failed write
is exactly the case worth tracing. And identifier order must not fragment the indexes of
tables that only ever grow.

## Decision

**UUIDv7 (RFC 9562), generated in the application, stored as PostgreSQL `uuid`.**

- Version 7 rather than 4: the leading 48 bits are a millisecond timestamp, so values
  increase over time. That gives locality in a b-tree instead of the random insertion
  scatter of v4, and `ORDER BY id` is chronological for free.
- Generated in the application rather than by the database, so an object has an identity
  from the moment it is logged, whether or not it is ever persisted.
- Generated by `uuid-utils` until Python 3.14 puts `uuid7` in the standard library.
- **Event ordering is a separate concern.** Delivery uses a strictly monotonic `bigint`
  sequence per run (ADR-0008); UUIDv7 is only ordered to the millisecond and would be an
  unsafe cursor.
- Identifiers are exposed unabbreviated in URLs and in the UI.

## Alternatives considered

### `bigserial`

Rejected: it requires a database round trip before an identifier exists, which breaks
logging that precedes the write, and it discloses volumes in public URLs.

### ULID stored as text

Rejected: the same ordering properties, but stored as `text` or `bytea` — worse indexes,
clumsier integration with `asyncpg` and Pydantic, and a non-standard format where a
standard one exists.

## Consequences

- A UUIDv7 discloses the creation time of the object it names. Within our threat model
  that is acceptable, and it is recorded here so nobody discovers it as a surprise.
- A pre-1.0 dependency sits at the centre of the identifier strategy. The escape route is
  short: UUIDv7 is a timestamp, a version nibble and random bits, roughly fifteen lines to
  implement if `uuid-utils` changes shape.

## How to invalidate

If runs need to be discussed out loud — "look at run 412" — a second, short, human-facing
identifier will be needed alongside this one.
